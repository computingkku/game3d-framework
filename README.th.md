# Game3D Framework (Godot 4.4)

Game3D Framework เป็นกรอบงานที่พัฒนาบน Godot Engine 4.4 เพื่อแสดงรูปแบบการจัดระเบียบโปรเจกต์เกมสามมิติอย่างเป็นระบบ โดยเน้นการแยกบทบาทของโมดูล การใช้ทรัพยากรข้อมูลภายนอก และการสื่อสารผ่านสัญญาณระหว่างองค์ประกอบที่เชื่อมโยงกันแบบหลวม (loose coupling)

## วัตถุประสงค์หลัก
- จัดทำโครงสร้างอ้างอิงสำหรับระบบตัวละครสามมิติครอบคลุมวงจรชีวิต เช่น การเคลื่อนที่ การต่อสู้ การรับความเสียหาย และการฟื้นคืนชีพ
- สาธิตการบูรณาการระหว่างสคริปต์ GDScript กับทรัพยากรเชิงข้อมูล (JSON/RES) เพื่อสนับสนุนแนวคิดการพัฒนาแบบ data-driven
- สนับสนุนการเรียนการสอน การทดลอง และการวิจัยเชิงปฏิบัติการ ด้วยฐานโค้ดที่ปรับใช้ซ้ำได้และมีภาระเชื่อมต่อระบบต่ำ

## โครงสร้างไดเรกทอรีสำคัญ
- `characters/` – ฉากและสคริปต์ของตัวละคร รวมถึงโมเดลสามมิติสำหรับการสาธิต
- `scripts/actors/` – ตรรกะหลักเกี่ยวกับตัวละคร (Actor3D, CharacterData, CharacterModel, PlayerData, MonsterData)
- `scripts/autoloads/` – บริการที่ถูกโหลดตลอดอายุการทำงาน เช่น GameManager, AudioManager, Types
- `scripts/inventory/` – ระบบคลังไอเท็มและผลกระทบของไอเท็ม (InventoryData, ItemData, ItemEffect, ItemHelper, LootItem)
- `objects/` – วัตถุเชิงกลไกเพิ่มเติม เช่น ดรอปไอเท็มและกระสุน
- `resources/` – ทรัพยากรข้อมูลสำหรับไลบรารีแอนิเมชัน (`ArrowLib.res`, `MeleeLib.res`, `ShooterLib.res`), รายการไอเท็ม (`items.json`), และ bone map (`Mixamo BoneMap.tres`)
- `resources/animations/` – คลิปแอนิเมชันแบบ `.res` (เช่น `idle_arrow.res`, `walk.res`, `run.res`)
- `scenes/`, `sky/` – ฉากสภาพแวดล้อมและสกายโดมที่ใช้ประกอบการทดสอบ
- `docs/` – แพ็กส่งออกสำหรับการสาธิตบนเว็บ (HTML5/WASM)
- `test/` – ฉากหรือสคริปต์ที่ใช้พิสูจน์แนวคิดเชิงเทคนิค

## ส่วนประกอบเชิงระบบ
- **Actor3D (`scripts/actors/Actor3D.gd`)**: คลาสฐานที่สืบทอดจาก `CharacterBody3D` รับผิดชอบฟิสิกส์ การเลือกแอนิเมชัน และการกระจายสัญญาณเหตุการณ์ (hp/mp/stamina, การตาย, การฟื้น)
- **CharacterData (`scripts/actors/CharacterData.gd`)**: ทรัพยากรเก็บค่าสถานะ ฟังก์ชันฟื้นฟู การคำนวณความเสียหาย และผลรวมจากอุปกรณ์สวมใส่
- **CharacterModel (`scripts/actors/CharacterModel.gd`)**: ควบคุมการเล่นแอนิเมชัน การยึดอุปกรณ์กับ bone และการปล่อยสัญญาณจังหวะโจมตี
- **Player3D / Monster3D (`characters/*.gd`)**: ตัวอย่างการสืบทอด Actor3D เพื่อเติมตรรกะอินพุตผู้เล่น การควบคุมกล้อง หรือพฤติกรรมศัตรู
- **ระบบคลังไอเท็ม (`scripts/inventory/`)**: จัดเก็บนิยามไอเท็ม คำนวณผลต่อค่าสถานะ และเครื่องมือเชื่อมต่อกับ JSON
- **GameManager (`scripts/autoloads/GameManager.gd`)**: ประสานสถานะส่วนกลาง เช่น ค่าแรงโน้มถ่วง การอ้างอิงผู้เล่น และการแจ้งเตือนผ่าน UI

## ระบบข้อมูลและแอนิเมชัน
- การแมปแอนิเมชันเก็บใน `resources/melee_animations.json` ควบคู่กับคลิป `.res` ใน `resources/animations/` เพื่อระบุ idle, walk, run, jump, attack, death และชุดเฉพาะอาวุธ
- รายการไอเท็มรวมอยู่ใน `resources/items.json` ระบุชนิด ผลต่อค่าสถานะ และข้อมูลเมตา (ราคา ความหายาก ฯลฯ)

ตัวอย่างข้อมูลจาก `resources/items.json`:
```json
{
  "id": "sword",
  "name": "Sword",
  "item_type": "WEAPON",
  "effect": { "states_add": { "attack": 6 } },
  "meta": { "price": 25, "rarity": "common" }
}
```

## เวิร์กโฟลว์การใช้งาน
1. ติดตั้ง Godot Engine 4.4 และเปิดโครงการผ่าน `project.godot`
2. รันฉากหลักด้วยปุ่ม F5 (กำหนดค่าไว้ล่วงหน้าแล้ว)
3. ใช้ชุดควบคุมสาธิต: `W/A/S/D` เคลื่อนที่, `Shift` วิ่ง, `Space` กระโดด, `X` หรือคลิกซ้ายโจมตี, `I` เปิด/ปิดคลังไอเท็ม, `Esc` สลับโหมดเมาส์
4. หากต้องการสาธิตบนเว็บ ให้นำไฟล์ใน `docs/` ไปเผยแพร่บนเซิร์ฟเวอร์แบบ static

## แนวทางการขยายผล
### การเพิ่มตัวละครใหม่
1. **กำหนดฐานการทำงาน**: สร้างฉากตัวละครใหม่ที่สืบทอดจาก `Actor3D` (สามารถคัดลอก `characters/Actor3d.tscn` เป็นฐาน) แล้วปรับค่าฟิสิกส์ แอนิเมชัน และสัญญาณตามต้องการ
2. **เลือกคลาสสืบทอดที่เหมาะสม**:
   - `Actor3D` สำหรับตัวละครทั่วไปหรือศัตรูที่ควบคุมด้วยสคริปต์
   - `Player3D` สำหรับตัวละครที่ผู้เล่นควบคุม มีระบบอินพุต กล้อง และตัวแปรช่วยการเคลื่อนที่ (เช่น coyote time)
   - `Monster3D` สำหรับศัตรูที่ต้องการโครงสร้าง AI พื้นฐานและระบบดรอปไอเท็ม
3. **จัดเตรียม CharacterData**: สร้างทรัพยากร `CharacterData` ใหม่ (หรือ `PlayerData`/`MonsterData`) กำหนดค่าสถิติพื้นฐาน ชุดอุปกรณ์ตั้งต้น และเชื่อมกับสคริปต์ผ่าน `_data`
4. **เชื่อมต่อโมเดลและแอนิเมชัน**: ตั้งค่า `model_scene` หรือเพิ่มโหนดโมเดลภายใต้ `Actor3D`, ปรับ `CharacterModel` ให้รู้จักคลิปแอนิเมชันและตำแหน่งติดตั้งอาวุธ หากใช้โครงกระดูกใหม่ให้ปรับ `Mixamo BoneMap.tres` หรือสร้าง bone map เพิ่มเติม
5. **บูรณาการกับระบบหลัก**: เพิ่มตัวละครในฉากทดสอบหรือฉากหลัก ปรับ `GameManager.player` (เมื่อเกี่ยวข้อง) และตรวจสอบการเชื่อมโยงสัญญาณกับ UI และ Inventory

### การเพิ่มระบบอาวุธเพิ่มเติม (ตัวอย่างอาวุธปืน)
1. **ทบทวนอาวุธที่มีอยู่**: ตรวจสอบนิยามดาบ (`sword`) และธนู (`bow`) ใน `resources/items.json` เพื่อเข้าใจรูปแบบข้อมูลและการอ้างอิงโมเดล/แอนิเมชัน
2. **เพิ่มรายการไอเท็ม**: เติมออบเจกต์ใหม่ใน `resources/items.json` เช่น
   ```json
   {
     "id": "handgun",
     "name": "Handgun",
     "item_type": "WEAPON",
     "effect": { "states_add": { "attack": 18 } },
     "meta": { "price": 150, "rarity": "rare" },
     "projectile": "res://objects/bullet/Bullet.tscn"
   }
   ```
3. **จัดเตรียมโมเดลและกระสุน**: สร้างฉากปืนและกระสุนใน `objects/` (เช่น `objects/bullet/Bullet.tscn`), ปรับ `CharacterModel` ให้รู้จักโหนดยึดปืน (`right_hand` หรือ `left_hand`) และกำหนดท่าถืออาวุธ
4. **ขยายตรรกะการโจมตี**: เพิ่มโค้ดใน `CharacterModel.gd` หรือสร้างสคริปต์ใน `scripts/weapons/` เพื่อสร้างกระสุนเมื่อเกิดสัญญาณ `attack`/`weapon_hit`, ตั้งค่าความเร็วกระสุน คูลดาวน์ และเสียงประกอบ
5. **ปรับชุดแอนิเมชัน**: เพิ่มหรือแก้ไขรายการ `shoot` ใน `resources/melee_animations.json` และสร้างคลิป `.res` ที่สอดคล้องใน `resources/animations/`
6. **ทดสอบและปรับจูน**: เพิ่มอาวุธใหม่เข้าคลังผ่าน `InventoryData.add_item_by_id`, ทดสอบการเล่นแอนิเมชันและการคำนวณความเสียหาย เพื่อรักษาสมดุลกับอาวุธที่มีอยู่

## การออกแบบสำหรับ Multiplayer
### สถาปัตยกรรมเครือข่าย
- แยก GameManager ออกเป็นสองบทบาท: **Server Authoritative Manager** สำหรับจำลองฟิสิกส์ สถานะตัวละคร และตรรกะการต่อสู้ และ **Client Presentation Manager** สำหรับแสดงผล UI/เอฟเฟกต์ โดยให้ Client ส่งอินพุตที่ผ่านการกรองไปยังเซิร์ฟเวอร์เท่านั้น
- ใช้ระบบ Multiplayer API ของ Godot (เช่น `MultiplayerAPI`, `SceneMultiplayer`) เพื่อประสานการสร้าง/ลบโหนด โดยกำหนดให้เซิร์ฟเวอร์เป็นผู้สร้างฉากตัวละคร (`Actor3D`, `Player3D`, `Monster3D`) และซิงโครไนซ์ค่าด้วย RPC/RSET

### การออกแบบตัวละครและข้อมูล
- ปรับ `Actor3D`, `Player3D`, `Monster3D` ให้ใช้รูปแบบ **state replication**: คงตรรกะฟิสิกส์ไว้บนเซิร์ฟเวอร์ และเผยแพร่เวกเตอร์การเคลื่อนที่ แอนิเมชัน และผลกระทบของไอเท็มไปยังไคลเอนต์ผ่าน RPC ที่มี rate-limit
- แยก `CharacterData` ออกเป็น **server copy** (อ่าน/เขียนเต็มรูปแบบ) และ **client shadow copy** (อ่านอย่างเดียว) เพื่อลดการแก้ไขโดยไม่ตั้งใจ และกำหนด serialization ของค่าที่จำเป็น เช่น hp/mp/stamina, สถานะ buff/debuff

### ระบบอาวุธและการโจมตี
- ให้อาวุธทุกชนิด (รวมถึงอาวุธปืน) ส่งคำสั่งโจมตีไปยังเซิร์ฟเวอร์ก่อนประมวลผล แล้วให้เซิร์ฟเวอร์เป็นผู้คำนวณ hit detection และความเสียหาย จากนั้นเผยแพร่ผลลัพธ์ไปยังผู้เล่นที่เกี่ยวข้อง
- เมื่อสร้างโปรเจ็กไทล์ (เช่น `objects/bullet/Bullet.tscn`) ให้เซิร์ฟเวอร์เป็นผู้สร้างอินสแตนซ์และกำหนด Network Authority เพื่อให้การคำนวณกระทบวัตถุสอดคล้องกันทุกเครื่อง

### การซิงโครไนซ์ UI และ Inventory
- ส่งเหตุการณ์สำคัญ (เช่น การเพิ่ม/ลดไอเท็ม, การเปลี่ยนสกิล) ผ่านสัญญาณบนเซิร์ฟเวอร์ แล้วทำ RPC ไปยัง Client เพื่ออัปเดต `InventoryData` แบบอ่านอย่างเดียว และสั่งให้ UI แสดงผลตามข้อมูลล่าสุด
- กำหนดคิวการแจ้งเตือน (`GameManager.notify`) ให้รองรับข้อความที่มาจากทั้งฝั่งเซิร์ฟเวอร์และไคลเอนต์ และใช้รหัสเหตุการณ์ (event code) เพื่อลดขนาดข้อมูลที่ส่งผ่านเครือข่าย

### ความปลอดภัยและการทดสอบ
- จำกัดคำสั่งที่ Client สามารถเรียกได้ เช่น อนุญาตเฉพาะ RPC สำหรับอินพุต/ปุ่มกด และใช้การตรวจสอบเวลาซ้ำซ้อน (server reconciliation) เพื่อลดการโกง
- ตั้งชุดทดสอบแบบจำลอง (Simulation Tests) ให้รันบนเซิร์ฟเวอร์โดยจำลอง latency/jitter และตรวจสอบว่า state ระหว่าง Client/Server ไม่แตกต่างเกินกว่าค่าที่กำหนด
## ข้อควรระวังเชิงเทคนิค
- การประเมินความเร็วแนวนอนใช้แกน `x` และ `z` เพื่อเลือกแอนิเมชันเดิน/วิ่งอย่างถูกต้อง (`Actor3D.gd:101`)
- การรีเซ็ต `action` ถูกย้ายไปหลังการตรวจสอบเสียงก้าวเท้าเพื่อไม่ให้พลาดการเล่นเสียง (`Actor3D.gd:147-156`)
- การแปลงชนิดใน `CharacterData.get_stat()` ใช้ `float(v)` เพื่อรักษาค่าต้นฉบับ (`CharacterData.gd:74`)
