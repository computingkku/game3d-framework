# Game3D Framework (Godot 4.4)

Game3D Framework เป็นกรอบงานที่พัฒนาบน Godot Engine 4.4 เพื่อใช้เป็นแม่แบบเชิงวิศวกรรมสำหรับการสร้างเกมสามมิติที่จัดระเบียบได้ง่ายและต่อยอดได้อย่างมีประสิทธิภาพ โครงการนี้ยึดหลักการแยกบทบาทของโมดูล การพึ่งพาทรัพยากรข้อมูลภายนอก และการสื่อสารระหว่างส่วนประกอบผ่านสัญญาณเพื่อลดการพึ่งพากันโดยตรง (loose coupling)

## วัตถุประสงค์หลัก
- จัดทำโครงสร้างอ้างอิงสำหรับระบบตัวละครสามมิติที่ครอบคลุมวงจรชีวิตครบถ้วน เช่น การเคลื่อนที่ การต่อสู้ การรับความเสียหาย และการฟื้นคืนชีพ
- สาธิตการบูรณาการระหว่างสคริปต์ GDScript กับทรัพยากรเชิงข้อมูล (JSON/RES) เพื่อสนับสนุนแนวคิดการพัฒนาแบบ data-driven
- สนับสนุนการเรียนการสอน การทดลอง และการวิจัยเชิงปฏิบัติการด้านเกมคอมพิวเตอร์ ด้วยสถาปัตยกรรมที่ปรับใช้ซ้ำได้โดยมีภาระในการหลอมรวมต่ำ

## โครงสร้างไดเรกทอรีสำคัญ
- `characters/` – ฉากและสคริปต์ของตัวละคร รวมถึงโมเดลสามมิติสำหรับการสาธิต
- `scripts/actors/` – ตรรกะหลักเกี่ยวกับตัวละคร (Actor3D, CharacterData, CharacterModel, PlayerData, MonsterData)
- `scripts/autoloads/` – บริการที่บรรทุกตลอดอายุโปรแกรม เช่น GameManager, AudioManager, Types สำหรับสถานะรวมของเกม
- `scripts/inventory/` – ระบบคลังไอเท็มและผลกระทบของไอเท็ม (InventoryData, ItemData, ItemEffect, ItemHelper, LootItem)
- `objects/` – วัตถุเชิงกลไกเพิ่มเติม เช่น ระบบดรอปไอเท็มและวัตถุกระสุน
- `resources/` – ทรัพยากรข้อมูลสำหรับแอนิเมชัน ไลบรารีแอนิเมชัน (`ArrowLib.res`, `MeleeLib.res`, `ShooterLib.res`) รายการไอเท็ม (`items.json`) และ bone map (`Mixamo BoneMap.tres`)
- `resources/animations/` – ชุดแอนิเมชันในรูปแบบ `.res` (เช่น `idle_arrow.res`, `walk.res`, `run.res`)
- `scenes/`, `sky/` – ฉากสภาพแวดล้อมและสกายโดมที่ใช้ประกอบเวทีทดสอบ
- `docs/` – แพ็กที่ส่งออกสำหรับการสาธิตผ่านเว็บ (HTML5/WASM)
- `test/` – ฉากหรือสคริปต์สำหรับทดลองแนวคิดทางเทคนิคเพิ่มเติม

## ส่วนประกอบเชิงระบบ
- **Actor3D (`scripts/actors/Actor3D.gd`)**: คลาสฐานที่สืบทอดจาก `CharacterBody3D` ทำหน้าที่อัปเดตฟิสิกส์ คัดเลือกแอนิเมชัน และกระจายสัญญาณเหตุการณ์ เช่น การเปลี่ยนค่า hp/mp/stamina หรือสถานะการตาย
- **CharacterData (`scripts/actors/CharacterData.gd`)**: ทรัพยากรจัดการค่าสถานะ ฟังก์ชันฟื้นฟูตามเวลา การคำนวณความเสียหาย และผลรวมจากอุปกรณ์สวมใส่
- **CharacterModel (`scripts/actors/CharacterModel.gd`)**: โมดูลที่ควบคุมการเล่นแอนิเมชัน การยึดอุปกรณ์กับโครงกระดูก และการปล่อยสัญญาณสำหรับจังหวะโจมตีหรือการสิ้นสุดแอนิเมชัน
- **Player3D / Monster3D (`characters/*.gd`)**: ตัวอย่างการสืบทอด Actor3D ที่เติมตรรกะเฉพาะ เช่น การควบคุมอินพุตผู้เล่น การจัดการกล้อง หรือพฤติกรรมของศัตรู
- **ระบบคลังไอเท็ม (`scripts/inventory/`)**: จัดเก็บนิยามไอเท็ม การคำนวณผลต่อค่าสถานะ และเครื่องมือช่วยเหลือในการค้นหาไอเท็มจากข้อมูล JSON
- **GameManager (`scripts/autoloads/GameManager.gd`)**: ตัวกลางที่ดูแลสถานะร่วม ได้แก่ ค่าแรงโน้มถ่วง ผู้เล่นที่ควบคุมอยู่ รายการไอเท็มตั้งต้น และช่องทางแจ้งเตือนส่วนติดต่อผู้ใช้

## ระบบข้อมูลและแอนิเมชัน
- การจัดชุดแอนิเมชันอาศัย `resources/melee_animations.json` ควบคู่กับแอนิเมชันแบบ `.res` ภายใต้ `resources/animations/` เพื่อระบุคลิปสำหรับสถานะ idle, walk, run, jump, attack, death รวมถึงคลิปเฉพาะเมื่อใช้อาวุธประเภทต่าง ๆ
- รายการไอเท็มทั้งหมดบันทึกใน `resources/items.json` ซึ่งกำหนดชนิดไอเท็ม สถานะที่ได้รับผลกระทบ และข้อมูลเมตา (ราคา ความหายาก ฯลฯ)

ตัวอย่างนิยามไอเท็มจาก `resources/items.json`:
```json
{
  "id": "sword",
  "name": "ดาบ",
  "item_type": "WEAPON",
  "effect": { "states_add": { "attack": 6 } },
  "meta": { "price": 25, "rarity": "common" }
}
```

## เวิร์กโฟลว์การใช้งาน
1. ติดตั้ง Godot Engine 4.4 แล้วเปิดโครงการผ่านไฟล์ `project.godot`
2. รันฉากหลักด้วยปุ่ม F5 (ฉากเริ่มต้นถูกตั้งค่าไว้ล่วงหน้า)
3. ใช้ชุดควบคุมพื้นฐาน: `W/A/S/D` เคลื่อนที่, กด `Shift` เพื่อวิ่ง, `Space` กระโดด, `X` หรือคลิกซ้ายโจมตี, `I` เปิด/ปิดคลังไอเท็ม, `Esc` สลับโหมดเมาส์
4. หากต้องการสาธิตผ่านเว็บ ให้เผยแพร่เนื้อหาในโฟลเดอร์ `docs/` บนเซิร์ฟเวอร์แบบ static

## แนวทางการขยายผล
- สร้างตัวละครใหม่โดยสืบทอดจาก Actor3D และเตรียม CharacterData/CharacterModel ให้เหมาะกับพฤติกรรมที่ต้องการ
- เพิ่มหรือปรับชุดแอนิเมชันโดยแก้ไข `resources/melee_animations.json` หรือสร้างไฟล์ `.res` เพิ่มเติมใน `resources/animations/`
- ปรับแต่งส่วนติดต่อผู้ใช้ภายใต้ `scenes/ui/` พร้อมเชื่อมสัญญาณกับ GameManager ตามความต้องการ
- ขยายระบบสถานะ (buff/debuff) โดยเพิ่มเติมตรรกะใน ItemEffect และการประมวลผลใน CharacterData

## ข้อควรระวังเชิงเทคนิค
- การประเมินความเร็วแนวนอนใช้แกน `x` และ `z` เพื่อความถูกต้องของการเลือกแอนิเมชัน (บังคับใช้แล้วใน `Actor3D.gd:101`)
- การรีเซ็ตตัวแปร `action` ถูกย้ายไปหลังขั้นตอนตรวจสอบเสียงก้าวเท้า เพื่อป้องกันการสูญเสียเหตุการณ์เสียง (บังคับใช้แล้วใน `Actor3D.gd:147-156`)
- การแปลงชนิดข้อมูลใน `CharacterData.get_stat()` ใช้ `float(v)` เพื่อรักษาค่าที่อ่านได้ (บังคับใช้แล้วใน `CharacterData.gd:74`)
